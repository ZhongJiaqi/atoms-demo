# Atoms Demo MVP：界面规格

## 1. 文档目的

本文档只描述本轮 REA 调研确认的两类界面：

1. Atoms 中文公开首页的首屏视觉布局与样式。
2. 已生成项目的 Agent 工作区布局与关键状态。

本文档不覆盖登录、定价、连接器、设置、支付、完整响应式规则或其他产品页面，也不包含实现代码。

## 2. 证据标记

- **观察：** 截图、DOM 或无障碍结构直接显示的内容。
- **推测：** 由多个观察结果推导，但没有直接执行证据。
- **实现建议：** 为 Atoms Demo MVP 提炼的复刻要求，不代表 Atoms 内部实现。
- **未知：** 当前证据无法确认，MVP 不应擅自当成事实。

## 4. 全局视觉语言

### 4.1 色彩

**观察：**

- 页面底色为近白或极浅暖灰，主要文字为接近黑色。
- 次级说明文字使用中灰；边框和容器分隔使用浅灰。
- 宿主产品的主要行动色为高饱和亮蓝，出现在“注册”“开始”“发布”“启用声音”等按钮，以及活动版本卡边框。
- Agent 头像是首页首屏最主要的多彩元素。
- 本轮观察到的生成应用拥有独立主题色；示例由朱红改为深蓝时，宿主工作区仍保持亮蓝主行动色。

**实现建议：**

- 宿主界面采用中性色底盘，只保留一个亮蓝主色。
- 生成应用必须在视觉上属于独立画布，不继承宿主主色。
- 禁用状态降低蓝色不透明度，不改变控件位置。

### 4.2 圆角、边框与阴影

**观察：**

- 顶部导航、按钮、公告、输入框和工具按钮大量使用胶囊或大圆角。
- 首页提示词输入区是白色大圆角卡片，配极浅边框和柔和阴影。
- 工作区 Viewer 使用大圆角外框；内部工具条和生成应用之间通过浅色分隔线区分。
- 版本卡为浅蓝底、亮蓝描边的大圆角矩形。

**实现建议：**

- 小型圆形工具按钮直径保持一致。
- 大容器使用 16–24 px 级圆角；胶囊按钮使用接近高度一半的圆角。
- 阴影只用于抬升主要输入卡或浮层，不给每个面板添加明显阴影。

### 4.3 字体与层级

**观察：**

- 首页主标题使用超大、粗重、紧凑的无衬线中文字体。
- 首页副标题明显缩小并使用中灰色。
- 工作区正文使用清晰的无衬线字体；本轮生成应用示例使用衬线字体和独立排版系统。
- UI 标签以简短中文为主，图标与文字并用。

**实现建议：**

- 宿主界面统一使用系统无衬线字体栈。
- Hero 主标题在桌面宽屏应形成首屏最强视觉锚点。
- 生成应用 iframe 内的字体和主题不受宿主排版令牌限制。

## 5. 首页首屏规格

证据：截图 `ev_c110…`；页面结构 `ev_75096127ab83eaffa70f9458b8c6b34a017d1a6acc636967e1eb387af29257a8`。

### 5.1 桌面布局

**观察：** 2400×1406 PNG 对应约 1200×703 CSS 像素的桌面视口。首屏为单列居中 Hero，顶部导航独立占一行。

从上到下依次为：

1. 顶部导航。
2. 大面积留白。
3. 浅灰公告胶囊。
4. 八个相互轻微叠放的彩色 Agent 圆形头像。
5. 超大主标题“把想法变成可销售的产品”。
6. 副标题“AI 员工用于验证想法、构建产品并获取客户。几分钟内完成。无需编码。”
7. 白色大圆角提示词卡片。

### 5.2 顶部导航

**观察：**

- 左侧：Atoms 黑色图形标志和品牌名。
- 中左：浅灰胶囊导航，包含“资源”“社区”“关于”“定价”。
- 右侧：“登录”浅灰按钮和“注册”亮蓝按钮。
- 导航左右贴近页面边缘，中间保留大量空白。

**实现建议：**

- 桌面端保持左右分布，不把所有入口堆在中央。
- “注册”是导航中唯一高饱和按钮。

### 5.3 Hero 与输入卡

**观察：**

- Hero 内容严格围绕水平中轴排列。
- 主标题大约占视口宽度一半以上，但保持两侧宽阔留白。
- 提示词卡接近 Hero 内容的最大宽度，内部留白充足。
- 卡片左下是圆形“+”入口；右下是亮蓝“开始 →”按钮。
- 输入提示位于卡片左上，不使用传统单行输入框外观。

**实现建议：**

- MVP 首页只需要复刻首屏关键层级，不需要实现首屏以下所有营销区块。
- 输入卡应支持多行文本；空内容时主按钮保持清晰但不可提交。
- 保持明显的上下留白，避免把 Hero 压缩成常规 SaaS 表单。

### 5.4 首页未知项

- 未直接观察移动端首页布局。
- 未确认 Hero 输入卡的所有焦点、错误和加载动画。
- 首屏以下虽在无障碍结构中确认存在能力区、信任区和 FAQ，但本轮没有对其视觉细节做规格化。

## 6. Agent 工作区规格

证据：无遮挡截图 `ev_9eb417…`；页面结构 `ev_512a773e3ca0d0ddc62c7ba7bbcf1ee079595c1630319962dee16c251dc3ece5`。

### 6.1 桌面三栏框架

**观察：** 2940×1602 PNG 对应约 1470×801 CSS 像素。工作区从左到右为：

1. **全局侧栏：** 约 50 CSS px，收起时只显示品牌/导航图标。
2. **对话与生成栏：** 约 450 CSS px，承载项目名、时间线、版本卡和后续输入框。
3. **App Viewer：** 占余下约 970 CSS px，是桌面端最大区域。

**实现建议：**

- 桌面端保持 Viewer 占比最大，避免对话区挤压生成应用。
- 中间栏和 Viewer 采用独立滚动；顶栏和底部输入区保持稳定。
- 最左全局栏可以在 MVP 中简化，但应保留品牌和项目/返回入口。

### 6.2 工作区顶栏

**观察：**

- 左侧显示项目名称“个人主页生成器”和下拉箭头。
- 中部靠右依次为历史入口、折叠控制、“应用查看器”胶囊和一组圆形工具按钮。
- 最右侧是“分享”和“发布”；发布是亮蓝主按钮。
- Agent 运行时出现“跟随智能体”，发布按钮变为淡蓝禁用状态；完成后恢复。

### 6.3 对话与生成栏

**观察：**

- 需求、Agent 说明、工具步骤、验证结果、交付总结和版本卡按时间纵向排列。
- 工具步骤有图标/类型、目标文件或动作名称，以及可展开的“显示 N 个更多”。
- 用户后续请求使用浅灰大圆角消息气泡。
- Agent 使用头像、姓名和角色标签（本轮为 `Alex｜工程师`）。
- 版本卡为浅蓝底、亮蓝描边，包含版本号和简短变更标题。
- 本轮捕获的空闲与运行状态中，底部均保留白色大圆角后续输入框；左侧为添加入口，右侧为语音和发送/停止按钮。

### 6.4 App Viewer

**观察：**

- Viewer 是有边框和圆角的独立大面板。
- 内部顶栏包含桌面/手机预览、刷新、Home 路由选择、新标签页和控制台。
- 生成应用直接在下方画布中运行；其自身导航和控件与宿主工具条分层。
- 本轮捕获的修改运行状态中保留上一个可用预览；完成后同一位置刷新为新版本。

**推测：** 生成应用很可能在跨域或 opaque iframe 中隔离；现有 frame/resource 证据支持这一判断，但未直接证明完整沙箱策略。

**实现建议：**

- MVP 使用 sandboxed iframe，并把 Viewer 顶栏留在宿主页面。
- 在新版本准备完成前继续显示上一个稳定预览。
- 加载、错误和刷新状态不得覆盖整个工作区。

### 6.5 临时浮层

**观察：** 工作区曾出现 PostHog 调研问卷和“启用声音通知”提示。

**实现建议：** 这两者不是核心 UI，不纳入 Atoms Demo MVP；截图和验收应以无遮挡工作区为准。

## 7. 工作区状态与运行属性

下表中“运行中可停止”是运行状态的共同属性，不是独立主状态。

| 主状态 | 运行属性 | 对话栏 | 顶栏 | Viewer | 版本区 |
| --- | --- | --- | --- | --- | --- |
| 空闲/已完成 | 可提交下一轮 | 普通输入框与发送箭头 | 发布可用 | 展示当前稳定版本 | 显示最近版本卡 |
| Agent 处理中 | 可停止 | 显示用户新消息、Agent 头像和步骤；发送按钮变为黑色停止方块 | 出现“跟随智能体”，发布禁用 | 本轮捕获状态中保留上一稳定版本 | 暂不新增版本卡 |
| 正在构建版本 | 不可提交新请求 | 显示完成说明 | 是否持续禁用发布未由截图直接确认 | 本轮实现建议继续显示上一稳定版本 | 显示“正在构建版本” |
| 新版本完成 | 可提交下一轮 | 输入框恢复发送箭头 | 发布恢复可用 | 切换为新结果 | 新增版本卡，可见“恢复到此版本”入口 |

## 8. 响应式边界

**观察：** App Viewer（应用查看器）提供桌面/手机预览切换控件。

**未知：** 本轮未截取宿主工作区在平板或手机视口下的布局，因此不能声称 Atoms 在窄屏使用何种栏位折叠规则。

**实现建议：**

- Atoms Demo 生成应用应支持窄屏预览；这是由已观察控件提炼的 Demo 要求，不是对 Atoms 产品需求来源的判断。
- MVP 桌面端优先严格复刻三栏结构。
- 窄屏宿主采用分段视图或抽屉，在“对话”和“预览”之间切换；这是 Demo 设计选择，不是 Atoms 已观察事实。

## 9. MVP 界面验收清单

- [ ] 首页首屏包含品牌导航、公告、Agent 头像、超大标题、副标题和大圆角提示词卡。
- [ ] 首页只使用一个宿主主行动色，整体保持高留白和中性色。
- [ ] 工作区桌面端清晰形成全局栏、对话栏和 Viewer 三个层级。
- [ ] 对话栏能同时展示消息、Agent 步骤、完成说明和版本卡。
- [ ] Viewer 拥有独立宿主工具条，生成应用在下方隔离运行。
- [ ] 处理中发送按钮切换为停止控件，发布进入禁用态，并保留上一稳定预览。
- [ ] 完成后新增版本卡、刷新预览并恢复发布按钮。
- [ ] 临时问卷和声音提示不属于 MVP 必需界面。
