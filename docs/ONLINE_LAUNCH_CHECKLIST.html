一、推荐的最小线上架构

浏览器
  ├─ 主应用：Vercel Hobby（Next.js）
  ├─ 登录/项目/消息/源码：Supabase Auth + Postgres + RLS
  ├─ 代码生成：DashScope OpenAI-compatible API
  └─ 生成应用
       ├─ 临时构建：Vercel Sandbox（限时、资源隔离）
       └─ 长期预览：每个成功版本发布为独立静态 Deployment URL

Sandbox 只承担不可信代码的短时构建，不承担长期预览；成功构建后的 dist 必须发布成可恢复的静态版本。这样 Sandbox 销毁后，iframe 仍可打开，项目恢复时也不必每次等待完整构建。

五、远程 Sandbox 与预览发布：上线前必须完成的代码工作

当前不能直接部署的原因

  • 现有 lib/sandbox/local-sandbox.ts 依赖 macOS sandbox-exec、本机目录和长期 Vite 子进程。
  • Vercel Function 文件系统与进程生命周期都不适合承载这种预览服务。
  • PREVIEW_PUBLIC_ORIGIN 只是 URL 模板，不会自动创建 DNS、代理或静态站点。

最小改造范围

  1. 新增 Sandbox 接口的 Vercel 实现，限制 CPU、内存、执行时间、网络和可写目录。
  2. 在 Sandbox 中装载数据库保存的文件并运行构建；继续保留最多两轮自动修复。
  3. 把成功构建的 dist 发布为独立静态 Deployment。
  4. 把部署 URL 和源码版本一起原子保存；项目恢复直接加载该 URL，缺失时再重建。
  5. iframe 只允许明确的预览 Origin；不得为了持久化把不可信应用与主站设为同源。

重要：这是工程阻塞，不是你再提供一个环境变量就会消失。我会在账号与变量就绪后接入并跑真实 E2E；在此之前只能证明本地受控 Sandbox 流程。

九、官方依据与明确边界

  • 观察：Vercel Sandbox 官方推荐在 Vercel 生产环境使用自动 OIDC；本地通过 vercel link 和 vercel env pull 获取开发凭证。Vercel Sandbox 文档
  • 观察：Vercel Hobby 当前 Sandbox 配额包括每月 5 小时 Active CPU、10 个并发 Sandbox、单次最长 45 分钟；超额后停止创建而不是自动收费。任务结束必须立即停止 Sandbox。Sandbox 价格与配额
  • 观察：Vercel REST API 创建 Deployment 需要 Access Token；每次部署会产生独立 URL。REST API · Deployment 概览
  • 观察：Hobby 旧 Deployment 有保留数量限制，因此 Deployment URL 不能替代数据库中的源码与版本快照；预览丢失时必须能从持久化源码重建。
  • 观察：Supabase 要求生产 Site URL 使用精确地址，Vercel Preview 可使用通配符回调。Redirect URLs
  • 观察：Supabase 默认 SMTP 有收件人和速率限制，不适合作为公开注册的生产邮件服务。SMTP 文档
  • 观察：Supabase Free 项目可能因一段时间低活动而暂停，且免费层没有可下载数据库备份保证。Production Checklist
  • 观察：Vercel 官方不在中国大陆运营服务器或 CDN 节点，vercel.app 访问可能被限速或阻断；自定义域名也不能形成可用性承诺。中国大陆访问说明
  • 推断：对于本月 1–2 位受控真实用户，免费层大概率足够；但这不是 SLA，也不能保证中国大陆跨境链路稳定。
