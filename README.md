# Atoms Demo：自然语言生成应用与交互预览

一个参考 Atoms 产品交互的 AI 应用生成 Demo。用户通过自然语言创建 React 应用，并在工作区预览、查看代码和继续修改；生成结果来自真实模型调用，执行状态与构建结果实时反馈。

在线体验：[https://atoms-demo-jiaqi.vercel.app/](https://atoms-demo-jiaqi.vercel.app/)

本项目使用 Codex 开发。

## 项目能力

- **生成与修改**：自然语言生成 React + Vite 项目，多轮对话修改同一项目；构建失败时读取真实日志，最多自动修复两轮。
- **真实预览**：受控构建、SSE 执行进度、iframe 可交互预览与 Preview / Code 切换。
- **项目恢复**：保存聊天、源码与成功版本，支持历史项目、刷新恢复和版本回滚；回滚创建新版本，保留历史。
- **认证与隔离**：邮箱注册、邮件确认、登录退出，以及按用户隔离的项目访问。
- **响应式工作区**：适配桌面和移动视口；首页以项目维度展示统一 UI 封面。

当前定位为少量用户的非商业演示产品，重点验证“需求 → 代码 → 构建 → 预览 → 连续修改”闭环，不等同于完整商业应用生成平台。

## 推荐验收流程

1. 注册并确认邮箱，登录后输入“创建 Todo App”。
2. 生成完成后，在预览中添加、完成或删除任务，并查看 Code 面板中的源码。
3. 继续输入“增加深色模式”，再输入“增加任务优先级”，观察同一项目的连续版本变化。
4. 刷新页面，或退出后重新登录，从“我的项目”恢复应用与对话；在历史记录中体验版本回滚。

生成应用的业务数据主要使用独立 Origin 下的 `localStorage`，支持当前浏览器刷新保留；聊天、源码和版本则保存在服务端。两者不同，当前不承诺业务数据跨设备同步。

## 技术架构

| 层级 | 技术 | 职责 |
| --- | --- | --- |
| 宿主应用 | Next.js 15、React 19、TypeScript、Tailwind CSS 4 | 首页、认证、聊天工作区、代码查看和预览容器 |
| Coding Agent | Node.js、OpenAI SDK、OpenAI-compatible API | 真实模型调用、文件生成、增量修改、校验及自动修复；线上使用 DashScope 的 `deepseek-v4.1-flash` |
| 生成项目 | React、TypeScript、Vite 6 | 在固定模板和受控依赖中构建可交互应用 |
| 认证与持久化 | Supabase Auth、Postgres、RLS、私有 Storage | 用户会话、项目/消息/源码/版本，以及成功构建产物 |
| 构建环境 | 本地 macOS Sandbox；线上 Vercel Sandbox | 短时隔离构建，限制文件访问、网络、资源和执行时间 |
| 预览与测试 | 签名预览网关、独立 Origin、iframe、Playwright | 应用隔离、预览恢复和浏览器端到端验收 |

```text
用户自然语言需求
  → Next.js API：认证 / 权限校验 / SSE
  → Coding Agent：生成或修改原项目源码
  → 隔离 Sandbox：类型检查 / 构建 / 日志修复
  → Supabase：保存成功快照与私有构建产物
  → 签名预览网关 + 项目独立 Origin
  → iframe：真实交互与后续修改
```

### 关键工程设计

- **宿主与生成应用分离**：工作区由 Next.js 承载，生成结果是独立的 React + Vite 项目；模型不能任意安装依赖或执行命令。
- **同项目增量迭代**：使用稳定的 `projectId` 关联源码、聊天与版本；云端通过项目租约、版本检查和事务化快照防止旧任务覆盖新结果。
- **线上构建与预览解耦**：线上 Sandbox 只负责短时构建，成功产物存入私有 Storage，由 Next.js 网关提供预览；线上不依赖长期运行的 Vite 进程，也不是每轮为生成应用创建一个独立 Vercel Deployment。本地开发则启动受控 Vite 预览进程。
- **可恢复与隔离**：进入工作区自动恢复预览，签名授权控制产物访问，项目独立 Origin 隔离宿主和生成应用；临时环境或授权过期不等于项目丢失。
- **有界模型输出**：首次生成及其构建修复使用 8,000 token 输出预算，增量修改及其构建修复使用 16,000；增量阶段只返回变化文件的完整内容。预算是单次输出上限，不是项目累计大小上限。截断或非法 JSON 会报错，不保存为成功版本；当前没有自动切换备用模型。
- **场景化设计引导**：Prompt 明确配色、排版层级、空状态和操作反馈，并以场景例子约束功能完整性；不依赖外部素材，尊重用户指定风格。视觉效果和业务正确性仍通过真实样本分别验证，不把提示词要求当作结果保证。

## 本地运行

完整本地生成流程目前要求 **macOS**（使用 `sandbox-exec`），建议 Node.js 24。Windows / Linux 的完整本地沙盒尚未适配。

```bash
git clone https://github.com/ZhongJiaqi/atoms-demo.git
cd atoms-demo
npm ci
cp -n .env.example .env.local
```

按 `.env.example` 配置本项目的模型服务和 Supabase 连接信息，并将 `APP_PUBLIC_ORIGIN` 设为 `http://127.0.0.1:3010`。如需与当前线上模型一致，将 `LLM_MODEL` 设为 `deepseek-v4.1-flash`；示例文件中的默认模型不代表生产配置。`cp -n` 不会覆盖已有配置；本地无需生产 Vercel 凭据，不要手动设置 `VERCEL=1`。

新环境需要在独立 Supabase Project 应用 `supabase/migrations/` 中的迁移，并配置认证回调 `http://127.0.0.1:3010/**`。邮箱确认保持开启，公开邮箱注册需要自行配置邮件发送服务；复用已有环境时不要重复初始化或覆盖线上认证地址。

```bash
npm run dev -- --hostname 127.0.0.1 --port 3010
```

打开 `http://127.0.0.1:3010`。本地默认使用项目独立的 `.localhost` 子域预览，`PREVIEW_PUBLIC_ORIGIN` 可留空。

## 验证方式

```bash
npm run typecheck
npm run build
npx playwright install chromium
```

测试包含模块级校验、认证与持久化集成，以及 Playwright 浏览器验收。代表场景包括任务管理、习惯打卡和个人记账，重点检查真实交互、刷新持久化、连续修改与跨账号隔离。

开发采用增量验证：优先运行受影响的测试，里程碑再做完整回归。真实模型和多账号用例需要对应测试配置，并会消耗服务商额度；配置缺失导致跳过不能视为通过。

截至 2026-10-14，线上全量首轮与定向修复补验累计有 41 个用例通过，1 个真实邮件注册用例未在本轮重验。修复后，正式站同项目 Todo → 深色模式 → 优先级三轮流程、刷新重登、旧任务保留及账号隔离通过；本地真实生成样本的三档优先级操作与主题刷新持久化也通过。相关 15 项模块测试、类型检查与正式部署构建通过。这是分轮验证结果，不表示再次运行整套后全部通过，也不保证任意生成应用都正确。

## 当前边界与后续优化

- **大项目迭代**：当前补丁仍返回变化文件的完整内容，源码上下文、文件数量和大小都有边界；16k 只是短期修复。后续计划按需读取相关代码、使用带原文校验的差异补丁，并通过多次受限调用后统一构建保存，尚未实现。
- **模型可用性**：尚未实现自动 fallback；服务商额度耗尽或模型不可用时，需要调整模型配置，不能保证自动切换。
- **执行可靠性**：完善失败消息、执行事件和修复结果的持久化，以及异常任务的恢复体验。
- **数据一致性**：将多表读取收敛为一致快照，继续完善并发修改和版本冲突处理。
- **资源管理**：完善中断任务的产物回收、配额管理、运行监控和成本提示。
- **体验与兼容性**：继续验证不同网络、真实移动设备、浏览器缩放、长对话与不同邮箱的投递表现。
- **暂缓功能**：Google 一键登录、分享和生成应用的独立公开发布尚未上线。
- **暂不扩展**：生成应用的多用户云端业务数据库与跨设备同步。

## 代码结构

- `app/`：页面与生成、恢复、预览 API。
- `lib/agent/`：模型调用、文件校验、创建/修改与自动修复。
- `lib/sandbox/`：本地和云端受控构建适配。
- `lib/cloud/`：私有产物、项目租约和签名预览。
- `lib/persistence/`、`supabase/migrations/`：项目存储、版本恢复和数据库迁移。
- `sandbox-template/`：固定 React + Vite 模板；`tests/`：单元与端到端测试。
